# Chiptune Studio — Development TODO

## 1. Project Overview

Create a lightweight desktop music production application focused primarily on chiptune music, with support for synthesizing sounds and creating sample-based instruments.

The application should be built using:

- **Language:** C++
- **UI Framework:** Raven UI (https://oscar-soirey.github.io/Raven/) (https://github.com/oscar-soirey/Raven)
- **Audio output:** Native audio playback engine
- **Audio format:** WAV (PCM)
- **Primary composition interface:** Piano roll

The application should prioritize simplicity, usability and a focused feature set.

It should not attempt to become a full Digital Audio Workstation (DAW). Avoid implementing unnecessary professional audio production features.

### Core philosophy

The application has two primary workflows:

1. Create and design sounds using a procedural sound generator.
2. Use generated sounds as samples in a piano-roll-based song editor.

Sounds should be independently exportable as WAV files and reusable across multiple projects.

Songs and individual tracks should also be exportable as WAV files.

[ ] Export complete songs as a mixed WAV file.

[ ] Support configurable export sample rates.

[ ] Support 16-bit PCM.

[ ] Support 24-bit PCM.

[ ] Support stereo and mono export where applicable.

[ ] Display export progress for longer exports.

[ ] Ensure exported audio has the correct duration and sample count.

### Export behavior

Track exports should render the selected track independently, without including other tracks.

Full-song exports should mix all unmuted tracks together.

Exported audio should be rendered from the project data rather than simply recording the real-time audio output.

This ensures consistent export quality regardless of playback performance.

# 9. Implementation Guidelines

- Use modern C++.
- Keep the audio engine independent of Raven UI.
- Prefer clear subsystem boundaries.
- Avoid unnecessary dependencies.
- Avoid implementing features before their dependencies are established.
- Keep the application usable throughout development.
- Build and test incrementally after each phase.
- Do not introduce speculative abstractions without a practical use case.
- Document important architectural decisions.
- Prioritize correctness and stability over feature count.

Before implementing Raven UI components, inspect the existing Raven UI framework and its documentation. Do not assume APIs or invent framework functionality.
